# 0.3.0 原生播放器功能

目标应用为手机正在使用的 `tv.danmaku.bili`，宿主仍为 9.12.0 (9120300)，补丁版本独立标记为 0.3.0。同一 BKS 证书签名，覆盖安装不清除数据。

## 入口与行为

- 我的 → 设置 → 去广告与空降助手 → **YouTube 风格手势**，默认关闭。
- 开启后，视频左侧 40% 双击后退 10 秒，右侧 40% 双击快进 10 秒，中间 20% 双击不操作；所有区域均不再用双击暂停。跳转保留播放/暂停状态，目标限制在视频范围内。
- 0.4.5 起，每次有效的双击快进/后退附带一次短促触感。中间区域、范围外、关闭手势、无有效时长、跳转失败或已在边界而没有移动时不触发；临近边界的实际跳转仍触发一次。沿用手势开关，尊重系统和播放器视图的触感设置。
- 0.4.5 同时去掉双击跳转的底部 Toast，改为播放器左侧/右侧的半透明弧面、方向箭头和秒数动画。同方向在 1.2 秒内再次双击，按每次 10 秒累计显示 10、20、30、40 秒；换方向、换播放器或停顿后重新从 10 秒开始。数字表示本轮请求的步进秒数，首尾位置仍按视频范围裁剪。最后一次操作后保持约 1.2 秒，再用 0.2 秒淡出。
- 单击呼出原生进度控件时，中间同时显示上一集、播放/暂停、下一集。上一集和下一集使用原生播放列表服务；不可用的方向变灰。保留原生进度条、音量、亮度和长按操作。
- 视频定时关闭菜单增加 **播放到当前视频结束**，横竖屏均有入口。它依赖真实播放完成事件，暂停不消耗倒计时，跳进度不会直接触发。完成后关闭播放页并阻止自动连播，不是关闭手机。
- 选择其他定时选项会取消本次“播放到结束”。切换到不同视频时取消，不把旧视频的定时意外带到下一集。
- 设置内 **自动检查更新** 默认开启；每天启动检查一次，也可点 **检查更新**。版本来自公开仓库 `LumiaBlack51/bili-clean-patch` 的最新正式 Release，忽略预发布和无效版本。不把官方宿主 9.12.0 当成补丁版本。
- 发现新版先提示，确认后用 Android 下载管理器下载该仓库的 `BiliClean-*.apk`，完成后打开系统安装器。安装仍需系统确认；自动检查开关不影响手动检查。

## 实现边界

固定宿主版本的适配检查在静态补丁阶段失败即停止。原生双击回调保留为关闭开关时的默认路径；播放完成在原生连播观察者执行之前处理。覆盖层只有三个按钮接收触摸，不铺设拦截进度拖动的透明全屏控件。

跳转动画使用播放器自身的 `ViewOverlay` Drawable，只绘制、不接收触摸，也不创建系统浮窗。关闭手势、播放器移除、尺寸/位置改变时立即清理；淡出后移除 Drawable 和帧回调，不常驻遮挡画面。

测试入口：`./scripts/build-host-tests.ps1` 生成独立 AVD instrumentation，然后运行 `app.biliclean.tests/.PlaybackControlsTest`。测试 APK 不进入交付 APK。

触感使用 Android `View.performHapticFeedback`，Android 14+ 使用 `SEGMENT_TICK`，旧系统使用 API 21 起支持的 `CLOCK_TICK`。不绕过系统开关、不新增震动权限；设备不支持或反馈调用异常时，跳转仍继续。设计依据：[Android 触感事件指南](https://developer.android.com/develop/ui/views/haptics/haptic-feedback)和[反馈常量](https://developer.android.com/reference/android/view/HapticFeedbackConstants)。具体强度由设备实现和系统设置决定。

`PlaybackControlsTest` 同时覆盖真实视频的触屏手势及受控触感分发：后者临时在真实宿主窗口放入记录视图、替换媒体引用，验证调用次数、无覆盖设置标志、边界、失败和不支持情况，结束恢复引用和视图。它验证调用策略，不能替代真机马达记录或人的手感体验。
